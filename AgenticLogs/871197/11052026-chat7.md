#### 2\. PerfilScreen — Bloquea la UI durante la carga de cosméticos

El init del ViewModel lanza cargarPerfil() y cargarCosmeticosDisponibles() en paralelo, pero la pantalla devuelve return en el if (cargando) antes de que los cosméticos terminen de cargar, y cuando cargando vuelve a false (solo gestiona el perfil), los cosméticos pueden aún no haber llegado. No es un crash, pero causa que los dropdowns aparezcan vacíos en la primera carga.  
kotlin  
// ✅ CORRECCIÓN en PerfilViewModel.kt: unificar ambas cargas bajo el mismo cargando  
fun cargarTodo() {  
    viewModelScope.launch {  
        cargando \= true  
        errorMessage \= null  
        try {  
            perfil \= cF.obtenerPerfilCase()  
            val todos \= cF.obtenerCosmeticosCase.obtenerTodos()  
            skinsEscalera  \= todos\[CategoriaCosmetico.ESCALERA\]  ?: emptyList()  
            skinsSerpiente \= todos\[CategoriaCosmetico.SERPIENTE\] ?: emptyList()  
            skinsFicha     \= todos\[CategoriaCosmetico.FICHA\]     ?: emptyList()  
            iconos         \= todos\[CategoriaCosmetico.ICONO\]     ?: emptyList()  
        } catch (e: Exception) {  
            errorMessage \= "Error al cargar perfil: ${e.message}"  
        } finally {  
            cargando \= false  
        }  
    }  
}
