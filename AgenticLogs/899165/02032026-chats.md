La respuesta corta es: **Depende de cómo hayas instanciado el ViewModel en tu NavGraph.**

Si seguiste el consejo anterior de instanciarlo **dentro del bloque `composable`** del NavGraph, la respuesta es **SÍ, se detendrá**, pero con un matiz importante sobre cómo funciona la navegación.

Aquí te explico los dos escenarios posibles:

### Escenario 1: Navegas a una pantalla "hacia adelante" (Sigue corriendo)
Si desde la pantalla de Amigos vas a la pantalla de Perfil (usando `SEState.goTo(Destinos.PERFIL)`), la pantalla de Amigos queda en el **Backstack** (la "pila" de pantallas guardadas).
* **El ViewModel NO muere**: Como la pantalla sigue existiendo por debajo, el `viewModelScope` sigue vivo.
* **El Polling SIGUE activo**: Se seguirá llamando a la API cada 2 segundos. Esto puede ser útil si quieres que al volver atrás la lista esté actualizada, pero gasta batería y datos.

### Escenario 2: Vuelves atrás o cierras la pantalla (Se DETIENE)
Si el usuario pulsa el botón de "Volver" o navegas destruyendo la pantalla de Amigos:
* El NavController saca la pantalla del Backstack.
* El **ViewModel se destruye** (se llama a su método `onCleared()`).
* El **`viewModelScope` se cancela automáticamente**.
* **El Polling se DETIENE** inmediatamente gracias al `while(isActive)` y al `delay()`. No tienes que hacer nada manual, Kotlin se encarga de limpiar el "hilo".

### ¿Cómo hacer que se detenga si la pantalla no está visible (Escenario 1)?

Si quieres que el polling solo funcione cuando el usuario está **viendo** la pantalla (para no gastar datos si está en el Perfil), tienes que usar el ciclo de vida de la UI, no el del ViewModel.

En tu **`AmigosScreen`**, añade esto:

```kotlin
@Composable
fun AmigosScreen(SEState: SENavHostController, viewModel: AmigosViewModel) {
    
    // LaunchedEffect con 'Unit' se lanza al entrar en la pantalla
    LaunchedEffect(Unit) {
        viewModel.setPollingActive(true)
    }

    // DisposableEffect se ejecuta cuando la pantalla DEJA de ser visible o se destruye
    DisposableEffect(Unit) {
        onDispose {
            viewModel.setPollingActive(false)
        }
    }

    // ... el resto de tu columna y UI ...
}
```

Y en tu **ViewModel**, añade ese flag:

```kotlin
private var pollingActivadoPorUI = true

fun setPollingActive(active: Boolean) {
    pollingActivadoPorUI = active
}

// Y en tu bucle de polling:
private fun iniciarPollingAmigos() {
    viewModelScope.launch {
        while (isActive) {
            // Solo hace la petición si está en la pantalla Y no está buscando
            if (!estaBuscando && pollingActivadoPorUI) {
                try {
                    listaAmigosOriginal.value = cF.amigosCase.obtenerAmigos()
                } catch (e: Exception) { /* ... */ }
            }
            delay(2000)
        }
    }
}
```

### Resumen
* **Si cierras la pantalla:** Se detiene solo (Limpieza automática del `viewModelScope`).
* **Si la dejas "debajo" de otra:** Sigue corriendo a menos que uses el `DisposableEffect` para pausarlo manualmente.

**Consejo de peer:** Para un juego de "Serpientes y Escaleras", el Escenario 2 suele ser suficiente. Si el usuario sale de la pantalla de amigos para ir a jugar, no pasa nada porque el polling se detenga solo al morir el ViewModel.

```kotlin
package com.UNIZAR_30226_2026_10.SerpientesYEscalerasReMix.ui.screens.Jugar_Crear

import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider
import androidx.lifecycle.viewModelScope
import com.UNIZAR_30226_2026_10.SerpientesYEscalerasReMix.domain.usecase.CaseFacade
import com.UNIZAR_30226_2026_10.SerpientesYEscalerasReMix.domain.usecase.Lobby
import kotlinx.coroutines.Job
import kotlinx.coroutines.delay
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.isActive
import kotlinx.coroutines.launch

class JugarCrearViewModel(private val cF: CaseFacade) : ViewModel() {

    // Factory para la inyección de dependencias siguiendo tu patrón
    companion object {
        fun Factory(cF: CaseFacade): ViewModelProvider.Factory =
            object : ViewModelProvider.Factory {
                override fun <T : ViewModel> create(modelClass: Class<T>): T {
                    return JugarCrearViewModel(cF) as T
                }
            }
    }

    // Exponemos el StateFlow del caso de uso directamente para que la UI lo observe
    val lobbyActual: StateFlow<Lobby?> = cF.jugarCrearCase.currentLobby

    private var pollingJob: Job? = null

    // Lógica de Polling similar a AmigosViewModel
    fun iniciarPollingLobby(lobbyId: String) {
        if (pollingJob?.isActive == true) return

        pollingJob = viewModelScope.launch {
            while (isActive) {
                try {
                    // Actualiza el atributo currentLobby en el caso de uso
                    cF.jugarCrearCase.obtenerEstadoLobby(lobbyId)
                } catch (e: Exception) {
                    // Manejo de errores de red silencioso para el polling
                }
                delay(3000) // Consultar cada 3 segundos
            }
        }
    }

    fun detenerPollingLobby() {
        pollingJob?.cancel()
    }

    // Métodos de interacción con el Lobby

    fun crearLobby(username: String) {
        viewModelScope.launch {
            cF.jugarCrearCase.crearLobby(username)
        }
    }

    fun unirseALobby(lobbyId: String, username: String, onSuccess: () -> Unit) {
        viewModelScope.launch {
            val exito = cF.jugarCrearCase.unirseALobby(lobbyId, username)
            if (exito) {
                onSuccess()
            }
        }
    }

    fun cambiarEstadoListo(lobbyId: String, estaListo: Boolean) {
        viewModelScope.launch {
            cF.jugarCrearCase.cambiarEstadoListo(lobbyId, estaListo)
        }
    }

    fun seleccionarMazo(lobbyId: String, nombreMazo: String) {
        viewModelScope.launch {
            cF.jugarCrearCase.seleccionarMazo(lobbyId, nombreMazo)
        }
    }

    fun añadirBot(lobbyId: String) {
        viewModelScope.launch {
            cF.jugarCrearCase.añadirBot(lobbyId)
        }
    }

    fun abandonarOExpulsar(lobbyId: String, emailAEliminar: String, onSuccess: () -> Unit = {}) {
        viewModelScope.launch {
            val exito = cF.jugarCrearCase.abandonarExpulsar(lobbyId, emailAEliminar)
            if (exito) {
                onSuccess()
            }
        }
    }
}
```

### Puntos clave de la implementación:
* **Gestión de Estado**: A diferencia de `AmigosViewModel` que usa `mutableStateOf` interno, aquí aprovechamos que `JugarCrearCase` ya tiene un `currentLobby` como `StateFlow`. La UI observará este flujo directamente.
* **Polling Dinámico**: El método `iniciarPollingLobby` requiere el `lobbyId` para realizar las peticiones `GET` correspondientes.
* **Consistencia**: Se mantienen las funciones asíncronas dentro del `viewModelScope.launch` para no bloquear el hilo de la interfaz de usuario.
