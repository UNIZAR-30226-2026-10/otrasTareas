El problema principal es que en **Jetpack Compose**, una `Row` intentará colocar los elementos uno al lado del otro, pero si los componentes `TabItem` son muy anchos o tienen un modificador `fillMaxWidth()`, el primer elemento ocupará toda la pantalla y "empujará" a los demás fuera de la vista (hacia la derecha, fuera del borde del móvil).

Para que se vean todos en una misma fila, como en la imagen que compartiste, debes usar el modificador `.weight(1f)` en cada uno.

### 1. El problema y la solución

Si no usas `weight`, la `Row` no sabe cómo repartir el espacio. Al ponerle `weight(1f)` a todos, les dices: "repartid el ancho de la pantalla en partes iguales".

Aquí tienes el código corregido para tu componente:

```kotlin
@Composable
fun MenuTopBar() {
    var selectedTab by remember { mutableStateOf("Jugar") }

    // Usamos FillMaxWidth para que la fila ocupe todo el ancho
    Row(modifier = Modifier.fillMaxWidth()) {
        // Cada TabItem debe tener .weight(1f) dentro para repartirse el espacio
        TabItem(R.drawable.jugar_icon, "Jugar", modifier = Modifier.weight(1f))
        TabItem(R.drawable.mazos_icon, "Mazos", modifier = Modifier.weight(1f))
        TabItem(R.drawable.logros_icon, "Logros", modifier = Modifier.weight(1f))
        TabItem(R.drawable.tienda_icon, "Tienda", modifier = Modifier.weight(1f))
        TabItem(R.drawable.perfil_icon, "Perfil", modifier = Modifier.weight(1f))
    }
}

### 2. Por qué usar `.weight(1f)`

En Jetpack Compose, si no especificas un peso, cada componente intenta ocupar solo el espacio que necesita su contenido (el icono y el texto).

* **Sin weight**: Si los iconos son pequeños, sobrará espacio a la derecha de la pantalla.
* **Con weight(1f)**: Le indicas a la `Row` que, después de calcular el espacio, reparta el ancho restante por igual entre todos los elementos que tengan este modificador. Como todos tienen `1f`, cada uno ocupará exactamente el **20%** del ancho de tu aplicación.

package com.UNIZAR_30226_2026_10.SerpientesYEscalerasReMix.ui

import androidx.compose.runtime.Composable
import androidx.compose.runtime.remember
import androidx.navigation.NavHostController
import androidx.navigation.compose.rememberNavController

// Definimos las rutas de forma constante para evitar errores de escritura
object Destinos {
    const val JUGAR = "jugar"
    const val MAZOS = "mazos"
    const val LOGROS = "logros"
    const val TIENDA = "tienda"
    const val PERFIL = "perfil"
}

class SerpientesAppState(
    val navController: NavHostController
) {
    // Aquí puedes añadir lógica de navegación personalizada
    fun navegarA(ruta: String) {
        navController.navigate(ruta) {
            // Evita acumular pantallas en la pila si el usuario pulsa muchas veces
            popUpTo(navController.graph.startDestinationId) { saveState = true }
            launchSingleTop = true
            restoreState = true
        }
    }
}

/**
 * Función helper para recordar el estado entre recomposiciones
 */
@Composable
fun rememberSerpientesAppState(
    navController: NavHostController = rememberNavController()
): SerpientesAppState {
    return remember(navController) {
        SerpientesAppState(navController)
    }
}

                        MenuTopBar(appState = appState) 
                    }
                ) { paddingValues ->
                    // El NavHost sustituye a tu bloque "when"
                    NavHost(
                        navController = appState.navController,
                        startDestination = Destinos.JUGAR,
                        modifier = Modifier.padding(paddingValues)
                    ) {
                        composable(Destinos.JUGAR) { Text("Pantalla Jugar") }
                        composable(Destinos.MAZOS) { Text("Pantalla Mazos") }
                        composable(Destinos.LOGROS) { Text("Pantalla Logros") }
                        composable(Destinos.TIENDA) { Text("Pantalla Tienda") }
                        composable(Destinos.PERFIL) { Text("Pantalla Perfil") }
                    }
                }
            }
        }
    }
}

```

---

## ¿Por qué hacerlo así?

1. **Desacoplamiento:** Tu `MenuTopBar` ya no necesita saber "qué pantalla toca", solo necesita llamar a `appState.navegarA(...)`.
2. **Estado real:** Si el usuario pulsa el botón "Atrás" del móvil, la navegación de Android funcionará automáticamente. Con tu `when` manual, el botón atrás cerraría la aplicación directamente.
3. **ViewModel-Friendly:** Cada pantalla dentro del `NavHost` puede tener su propio `ViewModel` de forma automática usando `viewModel()` de la librería de navegación.
